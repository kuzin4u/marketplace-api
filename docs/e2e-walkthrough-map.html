ПТК · сквозной прогон Системы E2E

Магазин → каталог → карточка → сделка

Карта сквозного прогона на живом API (Render + Supabase). Показывает каждый шаг, реальный эндпоинт, чем проверяем и на каком шаге упираемся в отсутствие банка. Зелёное — уже работает вживую, жёлтое — ждёт банк, красное — стоп-точка.

проверено вживую готово к прогону ждёт банк стоп-точка
1Вход продавцапроверено L3

Продавец входит в ЛК, получает токен со своим seller_id. Токен подставляется во все дальнейшие действия — подмена невозможна.

Инструмент
seller-login.html → форма логин/пароль
Эндпоинт
POST /api/v1/auth/login → JWT
Проверка
токен получен, внутри реальный seller_id
Условие
требует врезки auth-seller.js в server.js (написана, 15/15; если не врезана — можно временно взять seller_id из базы напрямую для прогона)
2Завести магазинпроверено L3

Продавец создаёт витрину: бренд, адрес, регион, каналы. Появляется запись shops с id вида SHOP-slug, авто-бот @slug_shop_bot, публичный адрес /s/slug.

Инструмент
shop-form.html → wizard 4 экрана
Эндпоинт
POST /api/v1/shops
Проверка
сервер вернул shop_id, магазин читается через GET /shop/:slug
Готовое
на проде уже есть SHOP-massamadre — можно прогон на нём, не создавая новый
3Каталог + карточка товарапроверено вживую

Продавец заводит товары. С visible_catalog=TRUE товар попадает в каталог Системы, с visible_shop=TRUE — на витрину. Уровень сервиса берётся из конфигуратора (трек B).

Инструмент
sku-crud.html → Quick add / CSV
Эндпоинты
POST /seller/:id/products · GET /catalog/categories · GET /catalog/search
Проверка
товар создан, виден в каталоге и на витрине; конфигуратор отдаёт его схему (SKU-005 зефир → ранг 2)
Готовое
6 боевых товаров: 4 хлеба + зефир + печенье, три схемы уже работают
4Покупатель: витрина → корзинаготово к прогону

Покупатель открывает витрину, кладёт товар в корзину. Сток резервируется атомарно (нельзя продать больше, чем есть).

Инструмент
vitrina-live.html → сетка карточек + корзина
Эндпоинты
GET /shop/:slug/products · POST /cart/add (409 при нехватке стока)
Проверка
товар в корзине, сток зарезервирован; повторный сверх остатка → 409
5Оформление заказаготово к прогону

Покупатель оформляет: имя, телефон, адрес. Сервер считает сумму сам, создаёт заказ. По entry_point определяется источник: SHOP → MIGRATED, CATALOG/агент → NETWORK (эскроу).

Эндпоинт
POST /api/v1/orders — items[{sku_id,qty}], сумма считается СЕРВЕРОМ
Результат
заказ ORD-… создан со статусом PENDING = вход в эскроу-контур
Проверка
GET /orders/:id возвращает заказ PENDING с верной суммой и составом
⬇ здесь упираемся ⬇
Стоп-точка: реальная оплата. Заказ создан и вошёл в эскроу (PENDING) — это предельная точка, докуда Система доходит сегодня. Следующий шаг — списать деньги с карты покупателя (СБП/эквайринг) и удержать их в эскроу до выдачи. Этого нет: платёж требует банка-партнёра (требования R1-R14), которого пока нет. Это архитектурный предел, зафиксированный в модели (Трек A стартует на СБП, R1 = блокер полной ценности, не запуска).
6Оплата → удержание в эскроуждёт банк

Покупатель платит (СБП/карта), деньги удерживаются на эскроу-счёте Расчётного Банка до подтверждения выдачи. Эскроу = authorization hold, растянутый до подтверждения.

Нужно
BankAdapter + Расчётный Банк (R1-R9 обязательные). Слой спроектирован (payment-platform-*), кода нет — ждёт партнёра
Сейчас
заказ висит в PENDING; можно вручную пометить как «оплачен» для прогона дальнейших шагов, но реального движения денег нет
7Выдача → клиринг → выплатаждёт банк

Продавец передаёт товар, покупатель подтверждает. Эскроу раскрывается: клиринг делит сумму (take-rate Системы vs выплата продавцу), деньги уходят продавцу за вычетом доли.

Логика
clearing_splits в базе есть, сплит считается; но раскрытие эскроу и реальная выплата — через банк
Визуализация
vitrina-live уже рисует поток 4 шага (заказ→эскроу→выдача→раскрытие) — как это будет выглядеть

Что реально прогоним сегодня

Шаги 1-5
полностью, на живом API: вход → магазин → каталог → карточка → корзина → заказ в эскроу (PENDING). Это и есть «провести сделку» в доступном сегодня смысле.
Шаги 6-7
показываем как визуализацию/схему (поток эскроу нарисован), но без реального движения денег — ждут банк.

С чего начать прогон

Быстрый
на готовом SHOP-massamadre — сразу шаги 4-5 (покупатель → корзина → заказ). Быстрее всего к «сделке».
Полный
с шага 1 — новый тестовый магазин, весь путь селлера + покупателя.
Карта сквозного прогона E2E · часть пула. Связанные: живая витрина, обзор сайта, каталог и расчёты массамадре, требования к банку R1-R14, размещение альфы, карта UI-этапа.
Интегрировано без сокращений в своды слоёв: сервисный слой (+параметры) и операционный слой (+параметры).
