Боевая авторизация продавца (JWT)

Закрывает главную дыру: seller_id больше не берётся из тела или URL запроса (где его мог подставить кто угодно), а достаётся из подписанного токена, полученного при входе. Для финтеха с эскроу это не опция — подменный seller_id означает выплату не тому продавцу.

Статус: модуль auth-seller.js написан и проверен локально на реальном PostgreSQL — 15/15 тестов, включая ключевой: подмена чужого seller_id в теле запроса игнорируется. Осталось врезать в server.js и задеплоить.

Что было не так

В текущем server.js прямо в коде помечено: // SELLER API (auth: seller role — simplified, no JWT yet). Маршруты берут seller_id из запроса:

// БЫЛО — seller_id из URL, ему можно подставить любое значение
app.post('/api/v1/seller/:seller_id/products', async (req, res) => {
  const seller_id = req.params.seller_id;   // ← кто угодно шлёт чужой id
  ...
})
Почему это опасно именно здесь. Любой залогиненный продавец мог создать магазин и товары от имени другого, а дальше — заказы и выплаты уходят по этому seller_id. В системе с эскроу это прямой увод денег. Не косметика — дыра в расчётном контуре.

Как стало

Продавец входит логином и паролем → получает подписанный токен, внутри которого зашит его seller_id. Сервер проверяет подпись и берёт seller_id из токена. Подделать нельзя — подпись не собрать без секрета сервера.

// СТАЛО — seller_id из токена, тело/URL игнорируются
app.post('/api/v1/seller/products', requireSeller, async (req, res) => {
  const seller_id = req.seller_id;   // ← из проверенного токена
  ...
})

Три эндпоинта модуля

МаршрутЧто делает
POST /api/v1/auth/registerзадать логин+пароль существующему продавцу (он уже в participants после KYC). Тело: seller_id, login, password (≥8). Проверяет, что продавец есть и роль SELLER
POST /api/v1/auth/loginлогин+пароль → { token, seller_id }. Один и тот же 401 на «нет логина» и «неверный пароль» — не выдаём, кто существует
GET /api/v1/auth/meпо токену вернуть свой seller_id — форма подтягивает его при загрузке

Плюс middleware requireSeller — вешается на любой защищаемый маршрут, кладёт req.seller_id из токена, отдаёт 401 без токена и 403 не-продавцу.

Таблица только одна новая — seller_auth. Модуль не трогает participants: учётные данные (логин, хэш пароля bcrypt, ссылка на seller_id) лежат отдельно. Создаётся автоматически при старте. Пароли хранятся только как bcrypt-хэш, в открытом виде — нигде.

Врезка в server.js — 4 шага

1

Установить зависимости

npm install jsonwebtoken bcryptjs
2

Положить auth-seller.js рядом с server.js и подключить

После строки app.use(express.json());:

const initAuth = require('./auth-seller');
const { requireSeller } = initAuth(app, { db, dbOne, genId });

Модуль использует ваши же хелперы db / dbOne / genId — ничего дублировать не нужно.

3

Защитить два маршрута и брать seller_id из токена

Магазин — добавить middleware и убрать seller_id из тела:

app.post('/api/v1/shops', requireSeller, async (req, res) => {
  const seller_id = req.seller_id;              // было: req.body.seller_id
  const { slug, brand_name, brand_accent, ... } = req.body;
  ...
})

Товар — убрать :seller_id из пути:

app.post('/api/v1/seller/products', requireSeller, async (req, res) => {
  const seller_id = req.seller_id;              // было: req.params.seller_id
  ...
})
4

Задать секрет на Render

В переменных окружения сервиса — JWT_SECRET (длинная случайная строка). Без него модуль работает на дефолтном ключе DEV-ONLY-CHANGE-ME — годится для локали, но не для прода.

JWT_SECRET = <длинная случайная строка>
JWT_TTL    = 12h            // опционально, по умолчанию 12ч

Что проверено локально (15/15)

Модуль прогнан на реальном PostgreSQL с настоящими HTTP-запросами (test-auth.js):

ПроверкаРезультат
Регистрация; повтор логина → 409; слабый пароль → 400; несуществующий/не-продавец → 404/400✓
Логин: неверный пароль и несуществующий логин → одинаковый 401✓
Магазин без токена → 401; с битым токеном → 401✓
Главное: Alice с токеном шлёт в теле seller_id: PTR-bob → магазин записан на PTR-alice (из токена)✓
Проверка в базе: подменный магазин реально принадлежит Alice, не Bob✓
Формы уже переведены на токен. Shop Form и SKU-CRUD больше не шлют seller_id в теле/URL — они кладут токен в заголовок Authorization: Bearer (берут из window.SELLER_TOKEN или localStorage, куда его положит страница входа после логина). На 401 показывают «нужен вход».

Что осталось

Модуль даёт вход по логину и паролю. Для полноценного прода останется связать POST /auth/register с реальным KYC/ЕСИА (сейчас пароль задаётся напрямую) и сделать страницу входа ЛК, которая кладёт токен в сессию. Но дыра с подменой seller_id закрывается уже этой врезкой — это главное.
