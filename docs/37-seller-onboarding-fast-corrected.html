Где теряем время в 7-шаговой процедуре

Из 48 часов целевого времени ~47 часов — ожидание, а не работа. Активное время селлера — менее 40 минут. Проблема не в сложности шагов, а в их последовательности и в паузах между ними.

Главный bottleneck. Не технология, а разрыв внимания: селлер уходит «почитать договор», «подготовить фото», «настроить потом». Каждый разрыв — 50% шанс не вернуться. Решение: не дать уйти — весь flow за одну сессию.

Новая модель: 3 фазы за 25 минут

7 последовательных шагов → 3 параллельных фазы. Селлер не ждёт ни на одном этапе. Система делает всё, что может, без участия человека, и спрашивает только то, чего не может угадать.

Модерация без ожидания: publish-first

Ключевое решение: SKU публикуется сразу, модерация проверяет фоном. Если ML уверен ≥ 85% — товар виден покупателям мгновенно. Если ML не уверен — товар виден только в магазине селлера (не в каталоге) до ручной проверки.

PUBLISH-FIRST МОДЕРАЦИЯ SKU создан │ ├──→ ML-модерация (2–5 сек): │ │ confidence ≥ 0.85: │ ├── status = ACTIVE │ ├── visible_shop = true │ ├── visible_catalog = true ← сразу в каталоге │ └── moderation_status = APPROVED_AUTO │ │ confidence 0.50–0.85: │ ├── status = ACTIVE │ ├── visible_shop = true ← виден в магазине! │ ├── visible_catalog = false ← не в каталоге до проверки │ └── moderation_status = PENDING_REVIEW │ → модератор: SLA 4ч │ → если approve → visible_catalog = true │ │ confidence < 0.50: │ ├── status = REJECTED │ ├── visible_shop = false │ ├── visible_catalog = false │ └── Уведомление: «Товар отклонён: причина» ЭФФЕКТ: · 85%+ SKU — в каталоге мгновенно (нет ожидания) · 10–14% SKU — в магазине сразу, в каталоге через 4ч · 1–5% SKU — отклонены (запрещённый контент) ЗАЩИТА ОТ ЗЛОУПОТРЕБЛЕНИЙ: · Первые 3 SKU нового селлера: publish-first в магазине, но в каталог — только после ручной проверки (SLA 4ч) · Post-publication review: случайная выборка 5% SKU проверяется вручную даже после авто-approve · Жалоба покупателя → немедленная ручная проверка
Без потери качества. Publish-first не значит «без проверки». ML проверяет за 2–5 секунд — это быстрее, чем человек, и с тем же уровнем точности для стандартного контента. Человек подключается только для edge cases (15% SKU). Post-publication review ловит false positives.

Юридика: click-wrap вместо подписания

Bottleneck «прочитать и подписать договор» устраняется переходом на модель click-wrap оферты — как при регистрации на любом сервисе.

Для ООО. Click-wrap достаточен для начала работы. КЭП — в течение 30 дней. Лимит GMV защищает обе стороны. После КЭП — лимит снимается.

ИТОГОВАЯ ФОРМУЛА Старая: 7 шагов × последовательно = 48 часов (35 мин работы + 47ч ожидания) Новая: 3 фазы × параллельно = 25 минут (25 мин работы + 0 ожидания) Ускорение: 115× (по общему времени) Ускорение: 1.4× (по активному времени селлера) Разница = не «селлер работает быстрее», а «система не заставляет селлера ждать». Главный вывод: bottleneck был не в сложности процедуры, а в её последовательности и разрывах внимания. Параллелизация + smart defaults + publish-first устраняют ожидание полностью.
