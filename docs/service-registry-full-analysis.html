Реестр сервисов — полный разбор

Развёрнутый анализ поверх базового реестра сервисов · главная ось — путь сделки от селлера к раскрытию эскроу

Базовый реестр описывает форму сервиса и не меняется. Этот документ раскладывает полный набор сервисов по оси процесса — от подключения селлера до раскрытия эскроу — и по каждому даёт классификацию, параметры, реалистичный тариф, обязательность, востребованность, связку с клирингом. Плюс: комплексирование по практике, модели заказа/конфигурирования и оценку полноты.

Семь фаз пути одной сделки. Сервис живёт на своей фазе; деньги стекаются вправо — к клирингу и раскрытию. Классификатор здесь = где на пути сделки работает сервис.

Классификатор

Главная ось — фаза процесса (выше). Поверх неё три вспомогательные оси разрезают набор иначе:

По предмету клиринга

  • СДЕЛКА — витрина, расчёт, эскроу, white-label, клиринг, раскрытие (ядро take-rate)
  • УСЛУГА — весь fulfilment, страхование, арбитраж (тариф за операцию)
  • КОМИССИЯ — продвижение, referral, кредитование (% за приведённую ценность)
  • — — онбординг, KYC, каталог, агент, корзина, антифрод (вне клиринга, инфраструктура)

По обязательности

  • Обязательные для сделки — онбординг, KYC, витрина, расчёт, эквайринг, эскроу, клиринг, раскрытие, корзина (без них сделки нет)
  • Опциональные по выбору — весь fulfilment, продвижение, referral, white-label, кредит, страхование (селлер решает)
  • Авто/фоновые — модерация, антифрод, возвраты, арбитраж (включаются по событию)

По исполнителю

  • Система/Организатор — витрина, каталог, расчёт, клиринг, продвижение
  • Участник сети — весь fulfilment (склады, логисты, ПВЗ, fulfilment-операторы)
  • Банк-партнёр — эквайринг, эскроу-флоат, кредитование, KYC
  • Внешний партнёр — страхование

Читается как приоритет доведения. Сначала ядро (фазы 1,6,7 — нужны всем), потом самые массовые опции (доставка, упаковка, продвижение), затем нишевые (white-label, страхование, арбитраж). Ровно этот порядок задаёт волны запуска.

Комплексирование — типовые связки по практике

Сервисы берут не поштучно, а готовыми связками под тип селлера. Шесть практических профилей:

Связь с клирингом

Правая часть оси — куда всё стекается. Каждый сервис попадает (или не попадает) в calculateClearing через свою роль:

Роль в клирингеПредметКакие сервисыКому уходит сплитСтатус в скелете
SYSTEM + ORGANIZERСДЕЛКАрасчёт (take-rate 12,5%)Организатор 2,5% + фонд поддержки 10%нет (надо врезать)
FULFILLMENTУСЛУГАхранение, приёмка, упаковка, сборка, возвратыfulfilment-операторы/склады по тарифуесть (общий)
LOGISTICSУСЛУГАдоставка, ПВЗлогисты/ПВЗ по тарифу зоныесть
ORGANIZER (сбор)СДЕЛКАтекущий сбор 0,2% (ст. 6.3)Организаторесть
SELLER (остаток)—то, что осталось после операторовселлер, 100% минус услугиесть
REFERRALКОМИССИЯпродвижение, referralОрганизатор/агентнет

Клиринг — общий знаменатель реестра. Реально calculateClearing держит FULFILLMENT / LOGISTICS / ORGANIZER 0,2% / SELLER (предмет УСЛУГА закрыт). Недостающие роли — SYSTEM (take-rate), REFERRAL, FINANCE, INSURANCE, HOLD — это предметы СДЕЛКА и КОМИССИЯ, уже определённые формой. Добавляются записями реестра + ролями в клиринге, без слома ядра.

Пробелы-кандидаты (зона роста)

Ещё не в реестре, но всплывают по логике пути. Каждый добавляется той же формой:

  • Аналитика/дашборд селлеру (сервис данных) — фаза 2/7
  • Ценообразование/репрайсер — фаза 2
  • Программа лояльности покупателя — фаза 3
  • Налоговый/ОФД-модуль (фискальные чеки) — фаза 6
  • Диспут-медиация (до формального арбитража) — фаза 7
Вывод по полноте. Ядро сделки (фазы 1, 6, 7) закрыто полностью — путь от подключения до раскрытия эскроу проходим сервисами реестра. Периферия (данные, лояльность, налоги, репрайс) — зона роста, не блокирует запуск. Реестр функционально полон для запуска и открыт для расширения той же формой.
