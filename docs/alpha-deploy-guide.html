Как разместить альфу

Два трека: A — статичное демо на GitHub Pages (5 минут, без сервера). B/C — живой конфигуратор на вашем Render + Supabase. Деплой на вашей стороне (у меня нет доступа к Render/Supabase); здесь — всё готовое и пошаговая инструкция.

Трек A · Демо на GitHub Pages 5 минут

Автономный дашборд — считает всё в браузере, показывает три схемы Массы Мадре, тумблеры кликаются. Сервер не нужен.

1
Возьмите файл alpha-demo-standalone.html (в архиве размещения).
2
Положите его в репозиторий, где живёт massamadre.ru (GitHub Pages) — например, переименовав в demo.html или в папку /alpha/.
3
Закоммитьте и запушьте: 
git add demo.html
git commit -m "alpha channels demo"
git push
4
Открывается по адресу вашего Pages, например massamadre.ru/demo.html. Готово — можно показывать.
Что показывает. Три категории Массы Мадре с их схемами (хлеб, кондитерка, выпечка), интерактивные тумблеры каналов и fulfilment, переключатель расчёта, живой пересчёт «ранга сервиса», кнопка сброса. Явная пометка «ДЕМО — не сохраняется». Ничего не шлёт наружу.

Трек B · Живой API на Render деплой

Врезаем конфигуратор в боевой server.js, миграцию — на Supabase. После этого дашборд может читать реальную конфигурацию.

Шаг 1 — миграция на Supabase

1
В Supabase SQL Editor выполните по порядку: 01_alpha_channels.sql → 02_seed_massamadre.sql → 03_resolver.sql. Первый создаёт таблицы, второй — данные Массы Мадре, третий — функции-резолверы.
Совместимость. Миграция использует CREATE TABLE IF NOT EXISTS — не конфликтует с существующими shops/skus/participants, если они уже есть. Новые таблицы: channels, visibility_rules, fulfilment_rules, settlement_rules, ratchet_log.

Шаг 2 — врезка модуля в server.js

2
Положите channels-api.js рядом с server.js. После строки app.use(express.json()) добавьте одну строку: 
require('./channels-api')(app, { db, dbOne });
Это тот же приём, что с auth-seller.js — модуль монтируется, используя ваши хелперы db/dbOne.

Шаг 3 — деплой

3
Закоммитьте channels-api.js + правку server.js, запушьте — Render пересоберётся. Появятся эндпоинты: 
GET  /api/v1/sku/:sku_id/config       // эффективная конфигурация SKU
GET  /api/v1/shop/:shop_id/service-map// уровень по категориям
PUT  /api/v1/visibility               // вкл/выкл канал (3 уровня)
PUT  /api/v1/fulfilment               // провайдер услуги
PUT  /api/v1/settlement               // режим расчёта
POST /api/v1/ratchet/upgrade          // повышение (только вверх)

Шаг 4 — проверка

4
В консоли браузера на странице вашего API (как делали L3): 
fetch('/api/v1/sku/SKU-bread-1/config').then(r=>r.json()).then(console.log)
// должно вернуть каналы хлеба: своя витрина + каталог

Трек C · Полностью живой (тумблеры пишут) бета

То же, что B, плюс дашборд не только читает, но и переключает через API.

5
Возьмите alpha-dashboard-live.html (переключённый на живой API, по образцу vitrina-live) — он читает GET /shop/:id/service-map и на клик тумблера шлёт PUT /api/v1/visibility.
6
Пропишите в нём базовый URL вашего API (как в vitrina-live: const API=...onrender.com) и разместите на Pages или в ЛК.
Прежде чем открывать запись всем. PUT-эндпоинты сейчас без авторизации — для беты добавьте requireSeller (из auth-seller.js), чтобы селлер менял только свой магазин. Иначе конфигурацию сможет переключить кто угодно.
