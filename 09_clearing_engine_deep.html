09 · Clearing Engine

Go · Расщепление платежа на N получателей · ст. 6.7, 3.5, 12.6

Роль в архитектуре ПТК

Clearing Engine — единственный сервис, который касается денег после эскроу. Получает от Deal Engine (01) событие «заказ подтверждён» → рассчитывает доли по тарифам из Registry (10) → отправляет инструкции в Escrow Service (02) на splitRelease.

Расчёт split (ст. 3.5: объём × тариф = сумма)

АЛГОРИТМ calculateSplit(order_id) func calculateSplit(orderID string) ([]SplitLine, error) { // 1. Получить заказ order := dealEngine.GetOrder(orderID) // 2. Получить привязку селлера → операторы binding := registry.GetBinding(order.SellerID) // 3. Получить тарифы каждого оператора tariffs := registry.GetTariffs( binding.FulfillmentID, binding.LogisticsID, binding.TrunkID, // nullable binding.WarehouseID, // nullable ) // 4. Рассчитать каждую долю var splits []SplitLine var totalOps float64 // 4a. Фулфилмент: тариф × количество единиц if binding.FulfillmentID != "" { qty := order.TotalQty() tariff := tariffs.Get(binding.FulfillmentID, "ASSEMBLY") amount := tariff.Rate * float64(qty) // Проверка: сборка пакетом (если qty ≥ 5 и есть тариф ASSEMBLY_BULK) bulkTariff := tariffs.Get(binding.FulfillmentID, "ASSEMBLY_BULK") if bulkTariff != nil && qty >= 5 { amount = bulkTariff.Rate * float64(qty) } totalOps += amount splits = append(splits, SplitLine{ ParticipantID: binding.FulfillmentID, Role: "FULFILLMENT", Amount: amount, TariffRef: tariff.ID, Calculation: fmt.Sprintf("%d ед × %.2f₽", qty, tariff.Rate), }) } // 4b. Логистика: тариф по зоне if binding.LogisticsID != "" { zone := resolveZone(order.ShippingAddress) // MSK → ZONE_1 tariff := tariffs.Get(binding.LogisticsID, "DELIVERY_"+zone) if tariff != nil { splits = append(splits, SplitLine{ ParticipantID: binding.LogisticsID, Role: "LOGISTICS", Amount: tariff.Rate, TariffRef: tariff.ID, Calculation: fmt.Sprintf("%s = %.2f₽", zone, tariff.Rate), }) // Логистика оплачивается из delivery fee, не из goods } } // 4c. Магистраль (межрегион, если есть) if binding.TrunkID != "" { route := resolveRoute(order.SellerRegion, order.BuyerRegion) tariff := tariffs.Get(binding.TrunkID, "TRUNK_"+route) if tariff != nil { totalOps += tariff.Rate splits = append(splits, SplitLine{ ParticipantID: binding.TrunkID, Role: "TRUNK", Amount: tariff.Rate, TariffRef: tariff.ID, Calculation: fmt.Sprintf("%s = %.2f₽", route, tariff.Rate), }) } } // 4d. Организатор: % от суммы товаров orgTariff := tariffs.Get("ORG-001", "ORGANIZER_FEE") orgAmount := order.TotalGoods * orgTariff.Rate / 100 orgAmount = math.Round(orgAmount*100) / 100 // округление до копеек totalOps += orgAmount splits = append(splits, SplitLine{ ParticipantID: "ORG-001", Role: "ORGANIZER", Amount: orgAmount, TariffRef: orgTariff.ID, Calculation: fmt.Sprintf("%.2f₽ × %.2f%%", order.TotalGoods, orgTariff.Rate), }) // 4e. Селлер: остаток (100% товара минус операторы) sellerAmount := order.TotalGoods - totalOps if sellerAmount < 0 { return nil, ErrNegativeSellerAmount{ OrderID: orderID, Goods: order.TotalGoods, Ops: totalOps, } } splits = append(splits, SplitLine{ ParticipantID: order.SellerID, Role: "SELLER", Amount: sellerAmount, Calculation: fmt.Sprintf("%.2f₽ − %.2f₽", order.TotalGoods, totalOps), }) // 5. Проверка: сумма splits = эскроу var checkSum float64 for _, s := range splits { checkSum += s.Amount } // Delivery оплачивается отдельно (из delivery fee) expected := order.TotalGoods // splits покрывают товарную часть if math.Abs(checkSum - expected) > 0.01 { return nil, ErrSplitMismatch{Expected: expected, Got: checkSum} } return splits, nil }

API: gRPC (внутренний) + REST (admin)

gRPC (между сервисами)

// clearing.proto service ClearingEngine { // Вызывается Deal Engine при переходе в CLEARING rpc ProcessClearing(ClearingRequest) returns (ClearingResult); // Вызывается Arbitrage при решении спора (ст. 12.6) rpc RecalculateClearing(RecalcRequest) returns (ClearingResult); // Получить split для заказа rpc GetSplit(SplitRequest) returns (SplitResult); } message ClearingRequest { string order_id = 1; } message RecalcRequest { string order_id = 1; string dispute_id = 2; string guilty_participant_id = 3; string guilty_role = 4; // SELLER | FULFILLMENT | LOGISTICS double refund_amount = 5; // сумма возврата покупателю } message ClearingResult { string clearing_id = 1; string status = 2; // COMPLETED | ERROR repeated SplitLine splits = 3; double total_released = 4; } message SplitLine { string participant_id = 1; string role = 2; double amount = 3; string tariff_ref = 4; string calculation = 5; string status = 6; // PENDING | RELEASED | ADJUSTED }

Пересчёт при споре (ст. 12.6)

RECALCULATE: виновник определён, пересчитываем split Вход: order_id, guilty=LOGISTICS, refund=350₽ Исходный split: SELLER 817.16₽ ✓ (не виноват — без изменений) FULFILLMENT 600.00₽ ✓ (не виноват — без изменений) LOGISTICS 350.00₽ → 0₽ (виновник — вся доля изымается) ORGANIZER 2.84₽ ✓ (не виноват — без изменений) Пересчитанный split: SELLER 817.16₽ → банк (без изменений) FULFILLMENT 600.00₽ → банк (без изменений) LOGISTICS 0.00₽ → ничего (доля изъята) ORGANIZER 2.84₽ → банк (без изменений) REFUND 350.00₽ → покупателю (из доли логистики) Банковские инструкции: 1. partialRefund(buyer, 350₽) — из эскроу обратно покупателю 2. release(seller, 817.16₽) — без изменений 3. release(fulfillment, 600₽) — без изменений 4. release(organizer, 2.84₽) — без изменений 5. release(logistics, 0₽) — ничего Правило: refund ≤ доля виновника. Если refund > доли виновника → ESCALATED (L2, ручной)

Интеграция с банком (Трек B)

ИНТЕРФЕЙС БАНКА (абстракция) interface BankAdapter { // Расщепление эскроу на N получателей SplitRelease(escrowID string, splits []BankSplit) (BankResult, error) // Частичный возврат покупателю PartialRefund(escrowID string, amount float64) (BankResult, error) // Статус расщепления GetSplitStatus(clearingID string) (BankStatus, error) } АДАПТЕРЫ (ст. 6.9): // Трек B: реальный банк (ПСБ / ВТБ) type PSBAdapter struct { ... } // Промсвязьбанк API type VTBAdapter struct { ... } // ВТБ API // Трек A: ручной клиринг (без банка) type ManualAdapter struct { ... } → SplitRelease: записывает инструкции в таблицу → Организатор вручную переводит деньги → Отмечает «переведено» в админке // Тест: mock type MockAdapter struct { ... } → Всегда OK, задержка 100ms ПЕРЕКЛЮЧЕНИЕ: config.bank_adapter = "manual" // Трек A (Волна 0–1) config.bank_adapter = "psb" // Трек B (после контракта) Один и тот же Clearing Engine, разный банковский адаптер.

Трек A: клиринг без эскроу

До подключения банка Clearing Engine работает с ManualAdapter. Расчёт split — автоматический (формула та же). Выполнение — ручное (Организатор переводит).

FLOW В ТРЕКЕ A 1. Покупатель платит → напрямую селлеру (карта, СБП, наличные) 2. Deal Engine → CLEARING 3. Clearing Engine: → calculateSplit (автоматически) → ManualAdapter.SplitRelease: записывает в clearing_instructions: «Фулфилменту 600₽, логистике 350₽, организатору 2.84₽» status = PENDING_MANUAL 4. Организатор в Admin Panel: → Видит список pending инструкций → Раз в неделю: агрегирует по участнику «Фулфилменту за неделю: 3×600 + 2×150 = 2100₽» → Переводит вручную (СБП / платёжка) → Отмечает «переведено» → status = RELEASED 5. Или: Организатор уведомляет селлера: «Вам поступило 1420₽. Из них 600₽ — фулфилменту, 350₽ — логистике, 2.84₽ — организатору. Переведите сами по реквизитам.» Минусы: ручной труд, задержка, нет эскроу-защиты Плюсы: работает без банка, формула та же Переход: config.bank_adapter = "psb" → автоматически
