Схема полного цикла

Пять уровней цикла

1. Инструменты селлера

Селлер проходит цепочку: join-form (ввод ИНН, проверка по ФНС, OTP-верификация, выбор группы) → wizard (бренд, slug, цвет, каналы — Telegram, сайт, VK) → sku-crud (добавление товаров: быстрое, ручное, импорт из CSV) → ЛК селлера (статистика, заказы, товары, операторы, настройки). Каждый шаг записывает данные в Supabase через API на Render.

2. База данных (Supabase)

PostgreSQL на Supabase (EU Frankfurt). 13 основных таблиц (participants, shops, skus, orders, clearing_splits и др.) + 2 таблицы каталога рынка (market_bakeries, market_products). Данные Масса Матере загружены через seed. Новые селлеры — через join-form → wizard → sku-crud.

3. API (server.js на Render)

Node.js + Express + pg. 20+ endpoints. Обслуживает витрину (GET /shop, /products, /config), каталог Системы (/catalog/search с ранжированием по ст. 11.3), корзину (POST /cart/add с атомарным резервированием), заказы (POST /orders с автоклирингом) и агента (POST /agent/chat — прокси к Claude API с промптом из двух каталогов).

5. Заказ → клиринг

Оба интерфейса ведут к одному endpoint: POST /orders → автоматическое расщепление (clearing_splits): селлер получает (100% – операторы), фулфилмент получает по тарифу, логистика — по зоне, организатор — 0.2% от суммы товаров.

Связь компонентов: wizard → витрина → агент

Прямой связи между wizard и витриной нет. Прямой связи между витриной и агентом нет. Связь — через данные в БД. Wizard создаёт запись в shops + skus → API отдаёт эти данные витрине (GET /shop/{slug}) и агенту (GET /catalog/search + POST /agent/chat). Агент — ещё один клиент того же API.
