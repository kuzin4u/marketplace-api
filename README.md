# marketplace-api

API и фронтенд Системы. Пилот — `massamadre.ru`.
Спринт 0: замена Google Sheets на PostgreSQL + REST API. Пилот работает
непрерывно, данные переезжают из Sheets в базу двойной записью.

**Живые адреса**

| Компонент | Адрес |
|---|---|
| API | `https://marketplace-api-ujfh.onrender.com` (Render) |
| Страницы | `https://kuzin4u.github.io/marketplace-api/` (GitHub Pages) |
| База | Supabase, проект `ykrsficzpmoevxpsezex`, EU Frankfurt |

> База находится за пределами РФ. Задача 0.0 плана реализации (ред. 3) —
> перенос в российскую юрисдикцию; жёсткий срок привязан к задачам 0.7–0.8
> (перенос истории и двойная запись). Подробности — в плане реализации.

## Запуск

```bash
createdb marketplace
psql marketplace -f schema/01_schema.sql
psql marketplace -f seed/02_seed_massamadre.sql

npm install
DATABASE_URL=postgresql://localhost:5432/marketplace \
JWT_SECRET="$(openssl rand -base64 48)" \
npm start
```

`JWT_SECRET` обязательна. Сервер должен падать при старте в её отсутствие,
а не подставлять значение по умолчанию — см. «Известные расхождения».

Проверка:

```bash
curl http://localhost:3000/api/health
curl http://localhost:3000/api/v1/smoke-test
curl http://localhost:3000/api/v1/shop/massamadre
curl http://localhost:3000/api/v1/shop/massamadre/products
curl "http://localhost:3000/api/v1/catalog/search?q=хлеб"
curl http://localhost:3000/api/v1/config/massamadre
```

## Маршруты

Базовый префикс — `/api/v1`.

### Покупатель

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/shop/{slug}` | магазин по адресу |
| GET | `/shop/{slug}/products` | товары магазина (`?cat`, `?sort`, `?page`) |
| GET | `/sku/{id}` | карточка товара — источник правды |
| GET | `/catalog/search` | каталог Системы (`?q`, `?cat`, `?price_min`, `?sort`) |
| GET | `/catalog/shops` | каталог магазинов |
| GET | `/catalog/categories` | дерево категорий |
| POST | `/cart/add` | добавить в корзину, атомарное резервирование |
| POST | `/orders` | создать заказ, автоматический клиринг |
| GET | `/orders/{id}` | заказ с позициями и расщеплением |

### Продавец

Требуют заголовка `Authorization: Bearer <token>`; токен выдаёт
`POST /auth/login`. `seller_id` берётся **из токена**, а не из URL или тела —
подмена чужого идентификатора игнорируется.

| Метод | Путь | Что делает |
|---|---|---|
| POST | `/auth/login` | вход, выдача JWT |
| POST | `/participants` | создание участника |
| POST | `/shops` | создание магазина |
| GET | `/seller/products` | товары продавца |
| POST | `/seller/products` | создать товар |
| PATCH | `/seller/products/{sku_id}` | обновить товар |
| GET | `/seller/stats` | статистика |
| GET | `/config/{slug}` | конфиг магазина для рендеринга витрины |
| GET | `/smoke-test` | штатный смоук-тест сервера |

> Маршруты `channels-api.js` и `customers-api.js` в этот перечень не входят:
> первый не врезан в `server.js`, второй нигде не описан. Перед использованием
> сверить с кодом.

Агентный слой (`/agent/*`) — отдельный сервис, деплоится независимо и в этом
репозитории не лежит.

## Известные расхождения

1. **`JWT_SECRET` не выставлен** в боевом окружении: подпись работает на
   значении по умолчанию. Токен подделывается тривиально, а `seller_id`
   в нём определяет, чьи товары и заказы видны. Задача 2.3 плана; от площадки
   не зависит, закрывается сейчас.
2. **Единицы цены.** Код принимает рубли (`price`), план тестирования требует
   копеек (`price_kop`), задача 0.2 предписывает копейки целым числом.
   Привести к одному нужно **до** переноса истории: товары пилота, заведённые
   до исправления, могут отличаться в сто раз, и ежедневная сверка будет
   ловить это каждый день.
3. **Формула клиринга в двух местах.** `calculateClearing` в `api/server.js`
   и её ручное воспроизведение в документе `pipeline-model-interactive.html`
   (598 строк скрипта). При изменении формулы демо продолжит считать по старой.
4. **`channels-api.js` не врезан** в `server.js`. Модуль написан, монтируется
   одной строкой.
5. **`customers-api.js` не описан** ни в одном документе пула.
6. **`seller-routes.js` лежит в корне**, а не в `api/`, в отличие от остальных
   модулей.
7. **Адрес API захардкожен** в страницах отдельной строкой в каждой.
   Заготовлена единая точка конфигурации (`config.js`, `window.API_BASE`) —
   не применена.
8. **Схема построена под редакцию 2** Правил; действующая — третья.

Реестр соответствия документов пула и кода — `docs/code-map.tsv`.
