## Удалить руками

| Что | Почему |
|---|---|
| `gitignore` (без точки) | заменён на `.gitignore`; git имя без точки игнорирует |
| `seed/02_seed_massamadre 2.sql` | дубликат. Рабочая версия — с `NOW()`, она в архиве |
| `.gitkeep` в `api/`, `config/`, `ops/`, `schema/`, `seed/` | каталоги наполнены, заглушки не нужны |

Про сид: файл, который раньше лежал как `02_seed_massamadre.sql`,
использовал `datetime('now')` — синтаксис SQLite. В PostgreSQL такой
функции нет, и он падал на последнем блоке, оставляя базу с данными,
но без клиринга. Рабочей была версия с суффиксом ` 2`; в архиве она
лежит под правильным именем.

## Что сделать после загрузки

**1. Дописать `.gitignore`, если он у вас уже был свой.** Файл в архиве
написан как полный, исходя из того, что рабочего `.gitignore`
в репозитории нет. Если окажется, что есть — не затирайте, слейте вручную.

**2. Подключить `config.js` в остальных страницах.** Две правки на файл,
для `shop-form.html`, `sku-crud.html`, `wizard-create-shop.html`,
`join-form.html`, `cart-checkout.html`:

```html
<script src="config.js"></script>
```

в `<head>` до основного скрипта, и строку

```js
const API = 'https://marketplace-api-ujfh.onrender.com';
```

заменить на

```js
const API = window.API_BASE;
```

Проверка: открыть страницу, в консоли должна появиться строка
`[config] API: ...`, во вкладке Network запросы уходят на прежний адрес.

**3. Выставить `JWT_SECRET`** в переменных окружения Render. Сейчас подпись
работает на значении по умолчанию. Сервер должен падать при старте
в отсутствие переменной, а не подставлять значение молча.

**4. Проверить контур:**

```bash
bash ops/smoke.sh https://marketplace-api-ujfh.onrender.com
```

Пункт «запись без токена отбита» покажет реальное состояние авторизации.

## Миграции применять отдельно

Файлы `schema/03_integrity.sql` и `schema/04_suborders_consents.sql`
загружаются в репозиторий, но **не применяются автоматически**.

`03` безопасна: добавляет ограничения, структуру не трогает, повторный
запуск не ломается. Останавливается, если в базе есть данные, нарушающие
новые правила, и показывает весь список сразу.

`04` необратима: колонки удалены, суммы пересчитаны в копейки, откат
только восстановлением из копии. Перед применением на боевой базе:

```bash
bash ops/dump-restore-verify.sh
```

После `04` код перестаёт совпадать с базой — исчезли `skus.price`,
`orders.seller_id`, `orders.shop_id`, `order_items.order_id`. Временная
опора — представление `orders_flat`. Правится в задаче 0.3.

## Чего в архиве нет

`shop-form.html` и `sku-crud.html` не включены намеренно: они уже есть
в репозитории, и какая версия свежее — неизвестно. Правьте свои
по инструкции выше.
