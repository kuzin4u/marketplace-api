Маршруты API пути селлера

Фактический перечень эндпоинтов из задеплоенного server.js — что дёргают формы shop-form и sku-crud. Базовый префикс — /api/v1. Маршруты уже реализованы на сервере; формы приведены к этому контракту.

Важно: сервер уже умеет все нужные маршруты — отдельный модуль подключать не нужно. Формы обновлены под реальные имена полей (brand_name, brand_accent, seller_id, цена в рублях). Проверка — Боевая авторизация (JWT) · план тестирования, уровень 3.

GET/api/v1/shop/:slugshop-form · проверка уникальности

Возвращает магазин с данными продавца и статистикой. Форма использует для проверки уникальности: 404 = адрес свободен, 200 = занят.

Ответ
200 → { shop_id, slug, brand, accent }   // магазин существует = адрес ЗАНЯТ
404 → { error: "not_found", slug }        // магазина нет = адрес СВОБОДЕН
200 занят404 свободен
POST/api/v1/shopsshop-form · создать магазин

Создаёт магазин. Требует существующего seller_id (продавец должен быть в participants). Slug проверяется на уникальность.

Тело запроса (реальный контракт)
{
  "seller_id": "SELLER-001",        // ОБЯЗАТЕЛЬНО, продавец из participants
  "slug": "massamadre",             // ОБЯЗАТЕЛЬНО, уникальный
  "brand_name": "Масса Матере",     // ОБЯЗАТЕЛЬНО (не "title"!)
  "brand_accent": "#8B4513",        // цвет (не "accent_color"!)
  "brand_tagline": "",
  "brand_description": "Хлеб…",
  "region": "Москва и МО",
  "category": null,
  "channels": { "telegram": true, "website": true, "vk": false }
}
Ответ
201 → { shop_id, slug, brand_name, url, bot, status }
201 создан409 slug занят400 нет seller_id/slug/brand_name или продавец не найден
POST/api/v1/seller/:seller_id/productssku-crud · создать товар

seller_id в пути, не в теле. Цена в рублях (поле price). Товар создаётся со статусом ACTIVE и модерацией PENDING.

Тело запроса (реальный контракт)
{
  "title": "Тартин",            // название
  "description": "Ржаной…",
  "price": 450,                 // РУБЛИ (не price_kop!)
  "stock": 10,
  "category_id": "CAT-BREAD",   // реальный id из GET /catalog/categories
  "tags": [], "images": [],
  "visible_catalog": true       // виден в каталоге/агенте
}
Ответ
201 → { id, status: "ACTIVE" }
201 создан400 у продавца нет магазина
POST/api/v1/ordersчекаут · создать заказ

Создаёт заказ. Сумма считается из цен активных товаров в базе, не из тела. entry_point определяет источник (SHOP→MIGRATED, CATALOG/REFERRAL_SYSTEM→NETWORK, ст. 10.4).

Тело запроса (реальный контракт)
{
  "customer_id": "CUST-001",
  "items": [ { "sku_id": "SKU-...", "qty": 2 } ],
  "entry_point": "SHOP",          // SHOP | CATALOG | REFERRAL_SYSTEM
  "shipping_address": { ... }
}
Ответ
201 → заказ с рассчитанной суммой и source_type
201 создан400 SKU не найден / неактивен

Подтверждено живым прогоном (L3, 20.08.2026)

Вся цепочка создана и прочитана обратно на живом Render + Supabase: продавец PTR-948a2938 → магазин SHOP-test-qa-1 → товар SKU-e7013d8b (Тартин, CAT-BREAD) → виден в витрине. Три факта, которые вскрыл живой прогон:

ФактКак выяснилосьУчтено
seller_group — ЧИСЛО (integer)значение «A» → invalid input syntax for type integer; сработало 1справочник (форма участника — в админ-панели, не в пуле)
category_id — реальный id из справочникавыдуманное «bread» → 500 Internal error; сработало CAT-BREADsku-crud: выпадающий список 7 категорий
7 фиксированных категорийGET /api/v1/catalog/categoriessku-crud подставляет их id

Реальные категории: CAT-FOOD Продукты питания · CAT-BREAD Хлеб и выпечка · CAT-PASTRY Кондитерские · CAT-CRAFT Крафт/handmade · CAT-DAIRY Молочные · CAT-HOME Товары для дома · CAT-FARM Фермерские. В проде sku-crud должна тянуть их живым запросом к /catalog/categories, а не хранить захардкоженными — если Организатор изменит список, форма подхватит.

seller_id — открытый вопрос интеграции. И POST /shops, и POST /seller/:id/products требуют seller_id существующего продавца. В проде он берётся из сессии ЛК после KYC; в формах пока подставляется SELLER-DEMO (переменная window.SELLER_ID). Для живого теста уровня 3 нужен реальный seller_id из вашей таблицы participants — создайте тестового продавца через POST /api/v1/participants и подставьте его id.
